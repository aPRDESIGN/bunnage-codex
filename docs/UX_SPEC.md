# Bunnage（仮）UX仕様

ゲームの原則は [GAME_SPEC.md](GAME_SPEC.md)、Demo v0.1の対象範囲は [DEMO_V01_SPEC.md](DEMO_V01_SPEC.md) に従う。本書の未決定事項は実装済み・確定済みとして扱わない。

## 画面構成と開始

- iPhoneの縦持ち・縦画面9:16、一人称視点。
- ステージへ入った直後に「最初に投げるものを選択する画面」を表示し、選択後にプレイを開始する。
- 通常プレイ中のUIは、中央付近の小さなHOLDパルス、最下部中央の現在アイテム／アイテム変更UI、小さなメニューボタンに絞る。
- アイテム一覧は常時表示しない。強度、スコア、残数、時間制限等を表示しない。
- 起動直後の遷移、各画面の詳細レイアウト、実機の画面比率・セーフエリアへの対応は未決定。

## HOLD

中央付近の小さな円形パルスは「ここを押さえる」と知らせる視覚ガイドであり、小さなボタンではない。実際のタッチ判定は画面中央の広い範囲とする。

- HOLD成立時に軽く短い触覚フィードバックを返す。
- 一度成立したら、腕を振って指が中央領域からずれてもキャンセルしない。指が画面に触れている限りHOLD状態を維持する。
- HOLD中のみ、投擲判定のためのモーションセンサーを監視する。
- HOLD成立から投擲終了まで、カメラ操作およびHOLD以外のUIをロックする。
- 指を離すことを投擲条件にしない。
- 振る前に指が画面から離れた場合は投擲をキャンセルする。HOLDを解除し、アイテムは投げずに手元に残し、HOLDパルスを通常状態へ戻す。
- スイング開始後、振り切りを検出して投擲成立となった後は、指が離れても投擲結果には影響させない。スイング開始後から投擲成立前までの指離れの扱いは未決定。

### カメラスワイプとの判別

- タッチ後、短時間ほぼ動かない場合はHOLDとする。
- タッチ後、すぐ一定距離以上スライドした場合はカメラスワイプとする。
- HOLD成立後はカメラ操作をロックする。指の位置がずれてもスワイプへ切り替えない。

HOLD判定時間は**0.15〜0.25秒程度を初期候補**とする。判定時間と移動量の閾値はハードコードせず、iPhone実機テストで容易に変更・比較できるパラメータにする。

## スイングと自動リリース

ユーザーは端末を握ったまま腕を振る。加速度・ジャイロ・端末姿勢等を使い、**振り動作 → ピーク → 減速・振り切り**を検出する。

振り切りが検出されたら、指が画面に触れたままでもゲーム側で自動リリースし、ゲーム内のアイテムを飛ばす。スマートフォンそのものは手から離さない。

| 段階 | 確定している挙動 |
| --- | --- |
| 通常時 | アイテム変更、メニュー、スワイプによるカメラ操作を利用できる |
| HOLD成立 | 短い触覚を返す。モーション監視を行い、他UIとカメラをロックする |
| スイング中 | 振り動作・ピーク・減速／振り切りを検出する |
| 自動リリース | 指離れを要求せず投擲し、必須の投擲時触覚を返す |
| 補充待ち | 投げたアイテムが手元を離れ、0.3〜0.5秒程度を目安に同じアイテムを自動補充する |
| 次の投擲 | 補充と、一度画面から指を離したことの確認を経て、次のHOLDを受け付ける |

### 投擲成立後から次の受付まで

1. 投げたアイテムが手元から離れる。
2. 0.3〜0.5秒程度を目安に同じアイテムを自動補充する。
3. ユーザーが一度画面から指を離したことを確認する。
4. 次のHOLDを受付可能にする。

一度指を離さない限り次の投擲には入らない。指が触れ続けている間に腕を元の位置へ戻しても、2投目として誤検出しない。0.3〜0.5秒は固定値ではなく、実機テストで変更・比較できる調整パラメータとする。

再受付条件は上記の通り確定。UI／カメラのロック終点である「投擲終了」をこの流れのどの時点とするか、およびスイング不成立時の復帰は未決定。

## 投擲方向と強度

**見ている方向 ＋ 腕を振った方向 = 投擲方向**を基本とする。

方向と強度の推定には、振った方向、振った強さ、スマートフォンの向き、回転、カメラ方向を利用する。体感と一致する方向へ飛ぶことを優先し、必要なら補正する。

| カメラ | 腕の振り | 意図する行き先 |
| --- | --- | --- |
| 正面を見る | 下へ振る | 正面の床 |
| 右を見る | 正面へ振る | 右方向 |
| 右を見る | 下へ振る | 右側の床 |
| 上を見る | 上へ振る | 高い場所 |

重点は正面・左・右・下への投げ分け。上方向も操作イメージとして扱うが、Demoの必須合格方向は前・左右・下とする。

LIGHT / NORMAL / HARDは内部的な強度の概念で、画面には表示しない。NORMAL程度で十分な速度と破壊を得られるようにし、必要に応じて強度に上限を設ける。

投擲検出・振り切り・方向補正・強度等の具体的な閾値は現時点で固定しない。ハードコードせず、後から容易に変更・比較できる構造にし、iPhone実機テストを通して調整する。

## カメラ

- プレイヤー位置は固定で、移動・歩行はない。
- カメラだけをスワイプで変更する。
- 水平方向は正面から左約90°、右約90°、合計最大約180°。
- 上下にも視点変更できる。初期候補は上約45°・下約60°。固定の最終角度ではなく、実機とステージを確認して調整する。
- 下方向は床へ物を叩きつけるため、上方向は照明・吊り戸棚等へ物を投げるために使う。真上・真下を見る必要はない。
- スマートフォン本体の傾きでカメラを操作しない。
- HOLD成立から投擲終了まで操作をロックする。
- 投擲物追尾、自動ズーム、カメラシェイク、自動カット変更は禁止。ゲーム側が勝手にカメラを動かさない。

中央領域でのHOLDとカメラスワイプは、前述のタッチ後の時間・移動量による判別に従う。

## アイテムダイヤル

1. 最下部中央に現在選択中のアイテムを表示する。
2. タップすると横方向のダイヤル／カルーセルを展開する。
3. 左右へ回してアイテムを変更する。
4. 中央に来たアイテムを一回り大きく表示し、その時点で選択中とする。

決定ボタンは不要。可能なら中央に来た際に小さな触覚を返す。別のアイテムを選ぶまで同じアイテムを無限補充する。ダイヤルの閉じ方や展開中の他入力の扱いは未決定。

## メニューと「きれいにする」

メニュー項目は以下の3つ。終了ボタンは設けない。

- ステージを変える
- きれいにする
- 設定

「きれいにする」の確認文は **「ステージをきれいな状態に戻しますか？」** とし、選択肢は **「きれいにする」／「キャンセル」** とする。「RESET」「元に戻す」という名称は使わない。

実行すると短く暗転し、破片、汚れ、凹み、壊れた物、倒れた物、移動した物を初期状態に戻す。キャンセルした場合は清掃を実行しない。暗転時間と清掃後のカメラ・選択アイテムの扱いは未決定。

同じステージでのプレイ中は、この操作を実行するまで見た目の散らかった状態を維持する。性能対策として物理演算停止・静的オブジェクト化・細かな破片の簡略化・表現統合を行っても、「壊した結果が勝手に片付いた」と感じる処理は禁止する。

「設定」の具体的な項目とDemoでの提供範囲は未決定。将来的には衝突時・破壊時の振動をON/OFFできるようにする。

## ステージ変更

「ステージを変える」でステージ選択画面へ移動する。Demo v0.1では離れたステージの状態保存は不要で、再度入った際は初期状態でよい。入場時には最初のアイテム選択を行う。

Demo対象は1ステージのみ。ステージ選択画面の具体的な構成・戻り方は未決定。

## 初回チュートリアル

初回のみ中央パルスを案内し、次の文を表示する。

**「ここを押さえたまま、スマホを振ってみよう」**

一度操作できれば常時説明は不要。初回の判定単位、操作完了の判定、案内を消すタイミング、端末を離さないことの案内方法は未決定。

## 触覚と音

| タイミング | フィードバック |
| --- | --- |
| HOLD成立 | 軽く短い振動 |
| 投擲成立 | 必須。短く明確な振動で「ゲーム内の物が手から離れた」感覚を作る |
| ダイヤルの中央到達 | 可能なら小さな振動 |
| 衝突・破壊 | 将来的に設定からON/OFFできるようにする。Demoでの採否は未決定 |

音は物によって変え、衝突後・破壊後の余韻も重視する。物ごとの音のイメージは [GAME_SPEC.md](GAME_SPEC.md) を参照。

## 実装前に解消する入力上の未決定事項

- 中央の広い判定範囲の具体的な寸法。HOLDとスワイプの判別方針は確定し、時間・移動量は実機で調整する。
- スイング開始後から投擲成立前までの指離れ、タッチ中断、複数指、アプリ中断からの復帰、スイング不成立時の復帰。
- UI／カメラのロック解除時点としての「投擲終了」の定義。補充と指離れ確認による再受付条件は確定。
- 通常の持ち替え等を投擲と誤認しないための具体的な判定方法。閾値を実機で調整可能にする方針は確定。
- センサー座標からカメラ基準への変換、左右の持ち手への対応。
