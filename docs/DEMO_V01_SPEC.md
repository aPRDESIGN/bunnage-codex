# Bunnage（仮）Demo v0.1仕様

本書は最初のデモで検証する範囲を定める。[GAME_SPEC.md](GAME_SPEC.md) と [UX_SPEC.md](UX_SPEC.md) を前提とし、未決定事項を実装判断で勝手に確定しない。

## 目的と最優先事項

最重要なのは、**HOLD → スマートフォンを振る → 自動リリース → ゲーム内の物が飛ぶ**という体験。グラフィック品質を最優先にしない。

iPhone実機で、端末を普通に握ったまま、全力を出さずに気持ちよく繰り返し投げられるかを検証する。

## 必須範囲

- iPhone想定、縦持ち・縦画面9:16、一人称、位置固定、歩行・探索なし。
- Demo Stage 01「日本の庶民的なキッチン」1ステージ。
- グラス・卵・缶の3アイテム。個数制限なし、選択中の同じアイテムを自動補充。
- 広い中央領域でのHOLD、領域外に指がずれても接触中は維持。
- HOLD中のモーション監視、スイング・振り切り検出、指離れを必要としない自動リリース。
- 振る前の指離れではHOLDを解除し、投げずにアイテムを手元に残し、パルスを通常状態へ戻す。投擲成立後の指離れは投擲結果に影響させない。
- 投擲成立後にアイテムが手元を離れたら、0.3〜0.5秒程度を目安に同じアイテムを補充し、一度指を離したことを確認して次のHOLDを受け付ける。指が触れ続けている限り次の投擲に入らず、腕を戻す動作を2投目として誤検出しない。補充時間は実機で調整する。
- タッチ後、短時間ほぼ動かない場合はHOLD、すぐ一定距離以上スライドした場合はカメラスワイプとする。HOLD判定時間の初期候補は0.15〜0.25秒程度で、時間と移動量はハードコードせず実機で調整する。
- カメラ基準の投擲方向、正面・左右・下への投げ分け、NORMAL程度で十分な投擲強度。
- HOLD成立時と投擲成立時の触覚フィードバック。
- 物理挙動、衝突、3アイテム固有の基本反応、結果の残存。
- 物ごとに異なる音と衝突・破壊後の余韻。
- スワイプでの左右・上下のカメラ操作。左右は正面から各約90°。
- 上下の初期候補は上約45°・下約60°。床へ叩きつける動作と照明・吊り戸棚等への投擲を目的とし、真上・真下は不要。最終角度は固定せず、実機とステージを確認して調整する。
- HOLD成立から投擲終了までのカメラ・他UIのロック。
- 入場時の初回アイテム選択、プレイ中のアイテムダイヤル、初回チュートリアル。
- メニュー項目「ステージを変える」「きれいにする」「設定」。設定項目の内容は実装前に確認する。
- ステージ選択画面への遷移、および確認・短い暗転を伴う「きれいにする」。

UI文言と操作はUX仕様に従う。補充・再受付条件とHOLD／スワイプ判別方針は確定。残る未決定事項は下記の確認項目として扱う。

## Demo Stage 01

**日本の庶民的なキッチン**。公営住宅や少し古めの一般的なマンションにありそうな雰囲気で、少し使用感・生活感がある程度とする。

- 高級住宅、モデルルーム、おしゃれなキッチンにしない。極端に汚くもしない。
- プレイヤー位置はキッチン真正面で固定。そこから左右合計最大約180°を見られる。
- 生活感を出す物：調味料、食器、タオル、家電、ゴミ箱、収納用品、日用品、メモ等。
- 禁止する物：人物、NPC、観葉植物、子どもを想起させる物、キャラクター雑貨、玩具、ファンシー雑貨。
- キッチンの骨格は完全破壊しない。

個々の配置物の種類・個数・反応対象は未決定。見た目の作り込みより投擲体験を優先する。

## 投擲アイテムと残存結果

| アイテム | 基本反応 | 残す結果 |
| --- | --- | --- |
| グラス | 割れる | 破片がその場に残る |
| 卵 | 潰れる | 壁や床等に跡・汚れが残る |
| 缶 | 凹む、跳ねる、転がる | 凹んだ缶が残る |

倒れた配置物は倒れた状態を残す。投げ続けるほどキッチンが徐々にめちゃくちゃになる体験を重視する。

性能維持のため、静止した破片の物理演算停止、静的オブジェクト化、非常に細かい破片の簡略化、必要に応じた破片表現の統合を許可する。ただし、**「壊した結果が勝手に片付いた」とプレイヤーが感じる処理は禁止**。同じステージでのプレイ中は、ユーザーが「きれいにする」を実行するまで、見た目の散らかった状態を維持する。

「きれいにする」では破片・汚れ・凹み・壊れた物・倒れた物・移動した物を初期状態に戻す。ステージを離れた際の状態保存は不要で、再入場時は初期状態でよい。

## 可能な範囲で追加する反応

以下は必須の投擲体験と3アイテムの基本反応より後に検討する。必須項目の不足をこれらの演出で置き換えない。

- ステージ側の食器が割れる。
- 小物が倒れる。
- 冷蔵庫等が凹む。
- 壁や床に汚れが残る等、ステージ側の反応を拡張する（卵の跡の残存は必須）。
- 投擲物 → 小物 → 別の物、といった物理連鎖。
- アイテムダイヤルの中央到達時の小さな触覚。

## 対象外・後続検討

- 人間・NPC・敵、HP、スコア、勝敗、ミッション、時間制限。
- 歩行、ステージ探索、投擲アイテムの個数制限。
- ゲーム内終了ボタン。
- 端末の傾きによるカメラ操作、追尾、自動ズーム、シェイク、自動カット変更。
- キッチン骨格の完全破壊。
- 追加ステージ・追加投擲アイテム、ステージ離脱後の状態保存。
- グラフィックの先行作り込み。
- 衝突時・破壊時の振動設定は将来方針。Demoで振動自体を採用するかは未決定。

## 合格条件と実機確認

| # | 合格条件 | 確認する体験 |
| --- | --- | --- |
| 1 | スマートフォンを普通に握って振るだけで投擲が成立する | HOLD中に振り切ると、指を離さず自動リリースされる |
| 2 | 前・左右・下方向への投げ分けが体感的に成立する | 意図した方向と飛ぶ方向が一致すると感じられる |
| 3 | 全力で振らなくても十分な勢いで飛ぶ | NORMAL程度の腕の振りで満足できる勢いが出る |
| 4 | 投擲時の振動で「ゲーム内の物が手から離れた」感覚が得られる | 自動リリースと短く明確な触覚が結びつく |
| 5 | グラス等を投げて壊した際に「もう一回投げたい」と感じられる | 飛ぶ・当たる・壊れる反応と音が爽快感につながる |
| 6 | 10回程度連続で投げても、面倒・必要以上の疲れ・投擲判定のストレスが生じない | 補充、再受付、方向判定を含めて繰り返しやすい |

これらをiPhone実機で確認する。評価者数、試行数、成功率等の数値基準は未決定であり、上記の体感条件を架空の測定結果で合格扱いにしない。

## 実装前に確認すべき事項

1. **入力の状態遷移**：中央判定領域の寸法、スイング開始後から投擲成立前までの指離れ、スイング不成立時の復帰、UI／カメラのロック解除時点としての「投擲終了」の定義。振る前のキャンセル、成立後の結果維持、補充・指離れ確認による再受付、HOLDとスワイプの判別方針は確定。
2. **投擲推定と調整**：センサーと座標系、方向補正、強度変換、NORMALの基準、誤検出への対処、持ち手への対応。値は実機調整で確定する。
3. **実機環境**：対象iPhone・iOS、触覚対応、検証用端末、ビルド・署名環境。Unity等の開発環境・バージョンも今回の仕様では未確定。
4. **UIの未確定部分**：実機画面比率対応、ダイヤルの閉じ方、1ステージでのステージ選択画面、設定項目、チュートリアル完了・初回判定、端末を離さない案内。上下角は上約45°・下約60°を初期候補として実機・ステージ確認で調整する。
5. **結果残存と性能**：性能予算、最適化の具体的な手法・適用条件。物理演算停止・静的オブジェクト化・微小破片の簡略化・表現統合は許可し、見た目の自動片付けは禁止する方針は確定。
6. **表現の範囲**：破壊・凹み・汚れの表現手法、配置物の反応範囲、連鎖の採否、音・素材の調達方法、清掃後のカメラと選択アイテムの扱い。
7. **検証手順**：合格条件を確認する評価者・実機・試行手順、誤検出や疲れの記録方法、アプリ中断・復帰時の扱い。
